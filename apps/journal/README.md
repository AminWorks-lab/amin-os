# 剧情档案

任务、线索、伏笔、编年史、事实与人物记忆、自动整理和前作参考共用一个聊天内应用。入口：`view.js` 的 `mount(target, options)`；服务入口：`service.js` 的 `getSharedService()`；共享 AI 可读取 `model.js` 的 `currentPrompt(ctx)`。所有布局直接使用 Amin UI 的 `amin-*` 语义类，不维护独立主题或宽度。

## 用户操作

- **任务**：目标、待开始／进行中／已完成／已放弃、0–100 进度、期限和奖励说明。可选择现有人物、地点、物品建立关联，也可填写稳定编号。进度 100 不会自动改为已完成；奖励仅是说明，不会写入背包或账本。
- **线索**：来源、可信程度、待验证／已确认、关联任务及人物／地点／物品。可信程度 100 不会自动确认或完成任务；关联任务删除后显示缺失，保留原编号。
- 两类记录复用档案事件、外置剧情快照和变量 2.0 的 `AminOS剧情.entries`，不新增独立存储。`save-task` / `save-clue` 走现有 AI 生成建议与审核流程。导入时同时导出的任务／线索会重映射任务编号，引用默认关闭。

- **伏笔**：标题、内容、关联人物、待回收／已回收／已放弃、来源楼层、可选剧情时间。可设置经过多少个后续楼层后在列表显示提醒；提醒不会自行给模型发送内容或推进剧情。
- **编年史**：手工整理或选择已加载的真实楼层范围，让 AI 起草。AI 的结果先出现在可编辑预览中，点击“采用草稿到正文”后仍须明确保存。
- **事实与记忆**：事实只存一份，确认程度分为已确认／未证实／有争议。人物记忆引用事实 ID 与人物稳定 ID，记录知情／传闻／遗忘、个人理解、可信程度、消息来源人物、获知时间与来源楼层。人物改名不改绑定；人物或事实删除后保留缺失提示，不按姓名重绑。遗忘保留事实与历史。
- **自动整理**：默认关闭，可设累计起点、每 2–1000 楼整理一次和附加要求。正常聊天生成结束后检查，每次处理一个已到间隔的范围，使用现有剧情档案 AI 渠道。只产生待确认草稿，审核保存后才新增编年史，引用仍关闭。相同分支、相同来源范围已生成／确认／忽略后不重复生成；手动重生成只更新同一待确认草稿。生成中换聊天、改来源或改资料后丢弃过期结果。Quiet、停止生成不会启动自动整理。
- **前作参考**：选择前作导出的档案 JSON，预览、勾选条目并明确核对来源后保存。每条保留前作名称、原档案 ID 和原文证据；不会声称这些内容是当前聊天楼层发生的事实。默认关闭引用，逐条核对后启用。普通 JSON 导入的前作参考也必须重新明确确认，不能沿用旧授权。
- **引用**：每条默认关闭。只有已保存、用户明确启用、属于当前分支且来源仍有效的档案参与提示。引用预览显示最终档案文本；超出字符上限会完整拒绝附加，不会截断事实。
- **导入／导出**：导出当前分支档案及原始来源正文。导入先验证和预览，再明确保存；生成新 ID，引用关闭，来源仅保留说明，须重新绑定本聊天实际楼层才能启用引用。

## 归属与来源

数据保存在当前聊天的 `chatMetadata.amin_os_journal_v1`，继续使用 version 1 与追加事件。不会自动共享到其他聊天。剧情时间读取场景应用的已确认时钟并作为快照保存；现实保存时间单独记录。新增可选 `autoChronicle` 配置与 `draftEvents` 历史，旧数据缺少它们时视为自动整理关闭、草稿为空。

所有建立、编辑、引用切换和删除均保存操作 ID、现实时间及操作发生时的完整消息前缀。消息证据包含发言者、用户标记、正文和回复候选编号。查询较早楼层或不同分支时，只回放精确匹配的事件，未来修改不会出现在过去。删除也是一个事件，不破坏较早分支的记录。

来源范围采用从 1 开始的界面楼层号，内部为从 0 开始、包含首尾的范围。保存每条原文和版本证据。改楼、删楼、切换候选或分支不匹配后，条目不再参与当前引用；可在“来源变化 / 其他分支”中查看保存时的正文，再主动复制为本分支新条目。导入及未绑定来源的手工条目也不能引用。

前作参考是上述当前楼层来源要求的明确例外：必须保存 `origin` 并由用户确认 `explicitReference`，才能在没有本聊天来源的情况下启用。提示中单独标记前作背景，不把它转换成事实或人物记忆。编年史与伏笔的普通导入仍要求重新绑定当前来源。

## 跨应用接口

- `readCharacterMemories(ctx, characterId)` 返回当前分支该人物的记忆、关联事实和缺失引用提示。人物卡打开 `journal` 后派发 `amin:select-character`，事件内容为 `{characterId, app:'journal'}`，切换到事实与记忆页并按 ID 筛选。也可使用 `mount(...).open({tab:'memory', characterId})`。
- `apps/linkage/adapters/journal.js` 提供只读数据与纯函数更新：`save-fact`、`save-knowledge`、`forget-knowledge`、`save-hook`、`save-task`、`save-clue`、`draft-chronicle`、`delete-entry`（旧名 `set_fact` 等仍作为别名接受）。不让模型改引用开关、自动整理设置或前作来源。编年史更新只写入待确认草稿。协调器负责整批校验和统一保存，适配器不自己写元数据或调用 AI。
- `readForPrompt(ctx)` 与用于校验的完整 `read(ctx)` 分开：提示只提供已明确启用且来源有效的条目，前作还需确认来源；未启用条目只暴露 ID、类型及不可引用标志。提示不包含前作保存的原文，也不从人物应用旁路解析姓名。关闭事实引用后，不会通过记忆附加该事实正文。
- 统一联动启用本模块后，旧 journal 临时提示停止附加；由统一条目提供允许读取的内容。
- `snapshotJournal`、`validateJournalSnapshot`、`restoreJournal` 供跨应用存档复用。快照保持兼容 `{version,limit,entries}`，新增可选 `autoChronicle`、`drafts`。恢复在当前分支追加事件，不覆盖旧历史；失效来源关闭引用并保留正文，失效草稿保留为忽略状态，旧快照恢复自动整理为关闭。

消息前缀用于保守判断，不能识别所有外部修改的历史语义。例如，更早的一条无关消息被修改，也会使之后建立的档案暂时离开当前分支；用户需核对并重新绑定。界面只处理宿主当前加载的 `ctx.chat`，不会自行加载未在当前上下文内的历史消息。

## AI 与保存

请求前冻结选定原文、现有正文、补充要求、渠道和共享预设；使用 `getAI().capture('journal')` 与 `generate('剧情档案 · 编年史', ...)`。编年史请求关闭持续效果、剧情档案和场景的附加引用，以维持用户指定的来源范围；用户自行配置的共享／酒馆预设仍按所选渠道生效。

生成期间切换聊天、来源改变、编辑框继续改动或其他窗口保存档案，旧结果均不采用。表单令牌同时检查聊天身份、元数据对象、消息前缀与档案基线。保存成功的令牌不会重复执行；失败时仅回滚本应用数据，保留编辑内容供重试。服务销毁与宿主消息事件会取消尚未完成的草稿。

模块支持宿主 `GENERATION_AFTER_COMMANDS` 的普通、重生成、切换候选和续写流程，生成结束／停止／聊天切换时清理临时提示。重生成与切换候选时排除将被替换的最后一条角色消息。缺少提示接口时，管理与复制预览仍可使用。

## 验证范围

`node --test test/journal-core.test.js test/journal-memory.test.js test/journal-view.test.js` 覆盖模型、宿主服务及 DOM 双替身交互。包括来源范围、过期与跨聊天结果、草稿确认、独立引用、前作导入预览、稳定人物关联、传闻／遗忘、保存失败恢复、自动整理幂等、统一提示的逐条授权和分支回放。

这些是离线测试。真实酒馆内的宿主事件时序、API 供应方返回、手机输入法与实际楼层窗口布局仍需要整体验收；测试通过不等于供应方请求或实际移动设备已验证。


任务可在能力面板的“行动结算”中关联推进并配置完成奖励。任务表单里的奖励说明仍是文字；只有行动结算中明确配置并确认的资源变化才会执行。插件维护 `rewardClaim` 领取收据，普通编辑保留收据，模型不得增删改；收据与任务一同进入剧情快照。
