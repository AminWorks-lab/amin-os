# 世界状态 · Amin OS 集成应用

世界状态可从两个位置打开：Amin OS 桌面入口在插件窗口中打开；最新非系统消息下的「世界状态」入口在楼层窗口中打开。两处都能编辑当前状态、生成或更新、管理规则和模板、浏览历史、调整显示并恢复备份，共用当前聊天的数据。切换入口时，当前编辑工作台显示在新选择的位置。关闭再打开 OS，会留在插件内的世界状态应用。

旧楼层打开只读快照，并提供「打开当前状态工作台」入口。浏览快照不会恢复历史变量。删除消息和切换回复仍沿用原有记录恢复规则；聊天切换、楼层删除、回复切换和新楼层出现时，旧的当前状态编辑器会关闭，避免继续编辑错误的上下文。

空聊天也可在 Amin OS 内编辑，第一条消息出现后仍保留在插件窗口。隐藏楼层按钮不会影响 OS 入口。手机上页签横向滚动，编辑器与表单使用单列和触控尺寸；窗口配色、字体和高度沿用 Amin OS 的统一外观设置。

开发验证：`node --test test/status-floor.test.js` 检查历史只读、楼层迁移、异步取消、宿主管理的消息挂载和隐藏清理。下面保留原独立状态栏的功能历史，其悬浮窗口和安装说明不适用于此 Amin OS 集成入口。

生成／补充／重新生成只经「AI 设置」中的世界状态渠道请求模型（Amin 独立接口、酒馆当前配置或指定酒馆连接配置）。原状态栏自带的地址、模型、密钥直连及 generateRaw 后备已移除；下方历史中有关“API 地址留空”或独立接口的说明不再适用，旧地址与模型可在「AI 设置 → 迁移旧配置 → 导入原地图 / 状态栏配置」导入为“原状态栏 API”（密钥需重新填写），再绑定到世界状态渠道。

## 按现有剧情更新状态

点击工作台顶部「按现有剧情更新状态」，或「生成设置 → 按当前剧情更新值」，进入同一份草稿面板。世界状态由统一联动管理时，这两个入口仍可使用。

1. 选择已有聊天楼层（界面从第 1 楼开始，默认最近最多 20 楼）；可另选角色卡、用户设定和世界书，并填写附加要求。
2. 点击「生成资料草稿」，通过世界状态 AI 渠道读取当前状态、所选来源和启用的更新规则。不会续写或重生成聊天正文。
3. 编辑、勾选建议并预览旧值、新值和依据，最后点击「确认保存整组资料」。即使日常联动处于自动模式，手动草稿也必须确认。

本入口只设置已有字段的最终值，保留数字、文本、布尔、字符串列表和进度类型；进度可设置整体或当前／最大值。不新增、删除、改名、转换类型或执行增减指令。空状态需先用生成／补充、模板或手动编辑建立。原有初始化、模板和日常聊天更新方式不变，旧的类型转换授权不会用于本入口。

手动请求可在联动总开关关闭时运行，但世界状态模块必须启用并允许读取、更新；缺少权限时会解释原因，不会自动修改设置。聊天、候选回复、当前资料、权限或状态规则变化会阻止陈旧建议。保存失败后使用「重试保存生成资料」，不会重复执行；关闭再打开工作台也可重试。世界书等异步来源在确认前再次核对。

自动回归覆盖服务和界面逻辑；`scripts/generation-browser-smoke.mjs` 提供隔离 Chromium 界面检查。真实酒馆、模型供应方、宿主保存落盘和手机触控仍需在目标环境验收。使用酒馆完整预设渠道时，宿主仍按其 Quiet 规则组装最终上下文，面板展示的是本次明确选择并提交的来源。

## 原独立状态栏功能历史

V1.11.3：项目内“添加变量”的表单在对应按钮下方展开，已有变量的“编辑 / 改类型”也在所属项目中展开。变量类型可选择文本、数字、布尔、列表、进度值，点应用后保存；不能转换的值需手动填写。添加项目仍在顶部。切换布局保留草稿，取消不修改数据。浏览器已验证表单定位及类型切换。

V1.11.2：进入编辑模式，点击已有变量的“编辑”，现在可修改名称。应用后保存，保留原值（除非同时编辑值）及显示位置；同项目重名会拒绝，保存前若变量已被其他操作更新则提示重新编辑。取消不改名。改名会改变变量路径，手写规则里引用旧路径的地方需要相应修改；历史快照保留当时名称。自动好感组合展示仍识别“好感度”和“好感阶段”这两个字段名。

V1.11.1：编辑模式中，每个字段增加“上移 / 下移”按钮，可在所属项目内调整显示顺序。顺序按角色和项目保存在当前设备，不改写变量值；新字段追加在末尾。普通模式好感度与阶段仍组合显示，组合行位置由好感度字段决定。楼层历史记录保留原有显示顺序。

V1.11：设置 → 毛玻璃窗口，开启半透明背景与16px背景模糊，透明度10%～80%，默认35%，默认关闭。修改立即生效并自动保存；兼容现有款式和配色。只让背景透明，不降低文字/按钮整体透明度。不支持背景模糊的浏览器可能只显示半透明；实际效果取决于WebView支持。窗口与内置状态卡共同透出聊天背景，不改变量和历史记录。

V1.10：状态窗口 → 设置 → 面板款式，新增古典书页、切角科技、角色档案、终端面板、极简平面。款式和五套配色独立搭配，默认古典书页小圆角。款式作用于窗口、状态卡片、规则卡片和楼层记录；修改自动保存到扩展设置，切换不重载编辑器。悬浮启动按钮仍保持圆形便于拖动。与状态栏的三种内容布局独立。

V1.9：状态栏本体新增卡片面板、紧凑列表、角色档案三种布局；点击项目标题折叠，编辑模式使用上下箭头排序。布局、排序与折叠按角色记在当前设备浏览器中，不写入模型变量、不随楼层回退。

时间/场景/世界项目中的日期、时间、时刻、地点、天气在顶部摘要显示。短文本左右排列，长文本上下排版；列表超过6项可展开。数字好感度与文本好感阶段并排显示，编辑模式仍分为独立字段。进度值继续显示进度条。

窗口打开期间检测到的变化短暂标记约12秒，数字显示差值；这是上一次面板读取后的变化，不是完整楼层差异。首次打开不标记。历史与消息楼层记录改善长文本排版，三种布局及变化提示用于当前状态编辑器。已检查语法、窗口集成与浏览器布局/折叠记忆；实际酒馆仍需更新验收。

V1.8.2：好感度生成强调拆为数字“好感度”和文本“好感阶段”，按规则表对应；跨区间时同步更新阶段。内置示例补充0为中性。已保存且启用的好感规则在编译时也追加成对字段要求，不覆盖用户规则原文。已有状态数据不会自动迁移，需编辑字段或重新生成；日常聊天请重新同步世界书。

V1.8.1：移除顶部扩展面板中重复的状态栏配置入口。全部功能通过悬浮按钮进入，关闭再打开窗口保留配置草稿。插件加载不再依赖扩展设置容器。

V1.8：状态规则页增加“规则分类”选择器：全体规则供当前酒馆用户的所有角色共用，角色规则仅用于当前角色（同卡不同聊天共用）。旧条目原样保留为角色规则，无需迁移。

按设定生成、补充、重新生成会合并两类中启用且适用于生成的条目；按钮更新合并适用于更新的条目，默认API与独立API均生效。“仅更新数值”的条目不会参与生成。提示词要求冲突时角色规则优先，这仍是模型提示约束。

复制更新提示词及同步世界书同样合并两类更新规则。全体规则修改后，生成/按钮更新立即使用；日常聊天需分别同步至各角色绑定的世界书，不会自动批量改写世界书。共用同一本世界书的角色仍共用最后同步的条目。

V1.7.2：将表单主题修复扩展到状态窗口所有页面及备份恢复弹窗，并修复下拉菜单选项被酒馆深色主题覆盖的问题。原有主题选择卡和激活页签保留各自配色。

V1.7.1：修正规则页表单被酒馆主题深色背景覆盖的问题。输入框、下拉框、规则内容、按钮和勾选色跟随状态栏所选主题；样式覆盖仅限本插件规则页。
规则条目默认折叠，点击标题展开／收起；标题显示启用状态及适用范围，新建条目自动展开。折叠不会关闭规则，也不会丢失编辑内容。

按角色卡与世界书生成动态状态栏，支持可视化编辑和备份恢复。纯前端扩展，无需构建或安装依赖。

## 安装

在酒馆或 TauriTavern 的“扩展 → 安装扩展”中填写仓库链接：

```text
https://github.com/agentgeleven-lab/world-status-hud
```

安装完成后刷新，打开悬浮状态按钮，在窗口的“生成”和“设置”页配置。

### 手动安装

1. 解压 ZIP，获得 `world-status-hud` 文件夹。
2. 将整个文件夹复制到酒馆目录下 `data/<你的用户目录>/extensions/`。
   默认用户通常是 `data/default-user/extensions/`；以你的实际目录为准。
   也可按全用户方式放到 `public/scripts/extensions/third-party/`。
3. 确保最终是 `extensions/world-status-hud/manifest.json`，不要多套一层文件夹。
4. 刷新酒馆，点击悬浮状态按钮进入窗口。

手动安装时不能把 ZIP 路径填进 Git 仓库安装框。
TauriTavern 本地扩展也使用其实际数据目录下的 `default-user/extensions/`；全局扩展使用数据目录下 `extensions/third-party/`，不要放进程序自带的 default 模板目录。
远程部署需要将文件上传到酒馆服务器的对应目录。
升级前备份旧的扩展文件夹，再替换文件并刷新。卸载删除该文件夹即可，聊天中的状态栏变量不会随之删除。

## 使用

### 状态规则库（V1.7）

打开 **状态窗口 → 状态规则**，点“新建规则”填写名称和提示词，也可点“添加好感度示例”导入内置示例后修改。示例不会默认启用，只有点击添加才建立启用的条目。

- 条目支持编辑、删除、启用开关，修改自动保存。按角色卡保存，同一卡的不同聊天共用，不同卡分别读取。
- 适用范围可选“生成与更新”“仅生成／补充”“仅更新数值”。启用且适用的条目全部参与提示，暂不提供关键词触发。
- 生成页的生成、补充和重新生成使用生成规则；“根据当前情况更新”使用更新规则。默认酒馆 API 和独立 API 均生效。
- 日常聊天需要点击“同步到世界书”，将当前启用的更新规则合入角色绑定世界书的本插件条目，并启用小白X变量管理2.0。后续修改、关闭或删除规则也需再次同步；关闭全部再同步可移除已写入的附加规则。
- “复制更新提示词”同时包含启用的更新规则。支持 `{{user}}`、`{{char}}`；规则保存于酒馆扩展设置，不是状态值或楼层快照。

规则是给模型的提示，不执行真正的1D3掷骰，也不强制校验好感度范围。示例保留用户提供的完整阶段表，包括正向最后一档101～120。原有字段类型保持不变：例如“75 - 值得信赖”仍是文本；如需纯数字好感度，请在编辑器中主动转换类型，并另设关系描述字段。

多个角色绑定同一本世界书时，会共用最近同步的更新条目；需要隔离日常聊天规则时使用各自的世界书。保存规则本身不修改状态值，也不会立即调用模型。

验证：通过规则隔离、启用与范围过滤、名字占位符、长度限制、世界书规则写入与移除、窗口页签和既有生成流程的模拟测试，并完成规则页面浏览器交互预览。尚未在实际TauriTavern中验证模型对规则的遵循效果。

### 五套界面主题（V1.6，已移除）

> Amin os 0.19.0 起，世界状态不再有独立配色：悬浮窗口、编辑器 iframe 和楼层记录统一跟随「设置 → 整体外观」的全局主题（`--amin-*`）。以前保存的状态栏主题设置会被忽略，不会报错。以下为历史说明。

更新并刷新后，打开 **状态窗口 → 设置 → 界面主题**，点击配色卡片即时切换并自动保存：

- **星港青蓝**：深色科技 HUD，青蓝与暖金。
- **樱花物语**：柔和视觉小说，浅粉与莓红。
- **旅人手记**：纸色、古铜与衬线字体，适合奇幻冒险。
- **深海紫晶**：靛紫夜色与淡紫高亮。
- **极简墨白**：白底石墨，适合清爽阅读。

主题同步应用于悬浮按钮、状态窗口、内置编辑器、模板预览和消息楼层记录。字体、背景、表单、按钮、进度条和边框一起调整。主题是此酒馆用户的扩展设置，不存入聊天变量，不影响模型输出与回退记录；不同设备仍按酒馆自己的设置同步机制处理。

切换主题不重载编辑器，未提交输入保留。默认使用星港青蓝，旧版本升级无需迁移状态数据。主题样式只作用于本插件，不改变酒馆其他区域。

验证：完成浏览器主题预览、浅深色显示、390px 窄屏溢出检查，以及切换主题保留编辑草稿的交互检查；窗口集成模拟测试通过。实际 TauriTavern 中仍请更新刷新后确认。

### 一键写入角色世界书（V1.5）

1. 在角色卡中绑定主世界书，打开该角色的聊天。
2. 点击悬浮“状态”按钮 → **设置 → 写入世界书更新提示词**。窗口生成页中的同名按钮也可使用。
3. 按钮在绑定的主世界书中新增 **世界状态栏 · 变量更新规则**，启用常驻（蓝灯），位置为角色定义之后。完成提示会显示世界书名及条目 UID。

条目使用 `{{xbgetvar_yaml_idx::状态栏}}` 动态读取本轮变量，并包含 `<state>` 更新语法、五种类型规则、避免重复增减、保护现有字段等要求。不会把当前数值固定写进世界书，也不会把浏览中的历史记录发给模型。没有当前状态时会让模型等待初始化。

请启用小白X的变量管理 **2.0**，然后正常聊天；本按钮只创建提示词，不代替小白X执行模型回复中的变量更新，也不自动请求模型。

重复点击只更新带本插件标记的条目；已有同名但未带标记的用户条目保留原样。如果你之前手动创建了同用途条目，可以自行停用重复规则。未绑定主世界书时只提示绑定，不自动新建世界书、不改角色卡的绑定关系。多个角色共用同一本世界书时都会使用这个通用条目。

其他条目（包括禁用、空条目）的内容和配置保持不变。写入前检查世界书是否发生变化；若编辑器存在未同步修改，会停止并提示先保存。更新本插件已有条目前，旧条目备份到当前聊天元数据 `world_status_hud_lorebook_backups`，最多保留最近 10 次，不放入模型变量。删除新建条目即可撤销该功能。

验证：通过新增、重复点击、同名用户条目保护、更新前备份、全部其他条目不变、无变量写入、聊天切换、世界书并发修改、保存失败等模拟测试。实际酒馆内的写入及模型回复效果仍需在更新后确认。

### 楼层记录与显示设置（V1.4）

- 打开悬浮“状态”按钮，进入新增的 **设置** 页，可开关“在消息末尾显示小型状态按钮”（默认开启，修改立即保存）。
- 消息末尾的 **◇ 状态** 按钮展开当前楼层的只读状态面板，再点一次收起；不会改变悬浮窗口的位置。
- 悬浮窗口的 **楼层记录** 页和楼层内面板都提供左右箭头、最新记录按钮。楼层显示从第 1 楼开始，对应当前对话的消息顺序（含用户消息）。
- 历史浏览完全只读。编辑、生成、按剧情更新以及复制模型更新提示词始终使用当前聊天变量 `状态栏`，不会因为正在看旧记录而切换数值。
- 删除后续消息，使旧楼层成为当前末尾时，自动恢复该楼层的记录，并关闭当前编辑窗口、取消扩展发起的模型任务，避免旧任务继续写入。只删除中间一条消息时不会恢复旧值。
- 切换末尾消息的候选回复时，优先恢复该候选已经记录的状态；新候选从上一楼的记录开始。历史页展示当前选中的候选。请避免删除、重排已有候选后再依赖旧候选编号的记录。
- 对安装前的旧消息不补造历史。若回退到没有记录的楼层，会提示并清除当前 `状态栏`，避免把未来数值送给模型；请在那个位置按剧情重新生成。原有记录仍保存在聊天元数据中。
- 每楼保存该楼最近一次状态快照，而不是每次字段修改的版本。新消息先继承当前状态；小白X或前端写入新的数值后继续更新当前末尾快照。已有聊天从安装后的当前末尾开始记录。
- 快照存放在聊天元数据 `world_status_hud_history_v1`，楼层标识放在消息 `extra.wsh_message_id`；它们不进入聊天变量命名空间，本扩展不会把历史记录附加到模型提示词。消息正文中已存在的状态文本不由此功能移除。
- 记录跟随聊天保存，不同聊天独立。关闭楼层按钮不会停止记录。楼层内为轻量 DOM 面板，兼容支持 ChatSurface 的 TauriTavern 消息挂载与卸载机制；旧版和 SillyTavern 使用普通消息挂载方式。
- 此版按 `context.chat` 为完整聊天数组的接口处理楼层；历史记录随聊天增长，占用空间也会增加。不支持只暴露局部聊天数组的旧实验性窗口接口。

验证：已通过逻辑及模拟界面测试（只读翻页、回退恢复、聊天隔离、重载、中间删除、无记录回退、按钮开关与清理、五个窗口页面）。尚未在你的 TauriTavern 实际会话中验证，请更新并刷新后试用。

### 模板、剧情更新与复制提示词（V1.3）

- 窗口新增“模板”页：输入名称，把已保存的当前状态存为模板。模板包含项目、变量类型和当前值，保存在扩展设置中，可跨角色使用。未应用的编辑草稿不会进入模板。
- 选择模板可预览。应用时可只补充缺失项，也可确认后替换全部；已有聊天状态先备份。模板为独立快照，后续编辑聊天不会修改模板。删除模板也不会删除聊天数据。
- “按当前剧情更新值”：使用生成设置中的API，读取角色卡、世界书、当前已加载的最近20条非系统对话及可选“当前情况补充”。只更新已有变量的值，保留原类型和结构，写入前备份。
- 在TauriTavern中，对话范围限于当前加载窗口，不会自动查询未加载历史。素材不设应用侧字符上限，不截断或自动删减；模型/API自身的容量限制仍适用。
- 模型更新期间若待改字段已被手动修改，则整次更新不写入；其他未涉及字段的变化会保留。没有新事实不应重复扣减数值，仍需检查模型理解是否正确。
- “复制模型更新提示词”：复制点击时的当前值、全部可更新路径及类型和输出规则，可直接粘贴到聊天输入框。不会自动发送消息。自动复制失败时会弹出选中文本供手动复制。
- 复制的是当时快照，状态变化后请重新复制。它不在用户消息中放入可执行的state更新块；模型回复时才应输出。让回复自动写入变量仍需要小白X变量管理2.0；插件的“按当前剧情更新值”按钮则不依赖小白X。


### 窗口内的生成设置

点击浮动“状态”按钮，窗口顶部可切换“状态栏”和“生成设置”。生成设置内可填写API、模型、世界书范围和要求，保存配置、生成／补充、重新生成整套、取消生成及恢复备份。生成完成后点“查看状态栏”即可返回显示页面。

窗口与扩展设置使用同一个表单和同一份配置。切换标签或关闭窗口不会丢失当前表单输入；仍需点保存配置或生成按钮保存设置。独立API密钥仍仅保存在本页面会话。窗口关闭后，可继续在扩展设置中操作；再次打开窗口时表单会移入窗口。

### 浮动按钮、窗口拖动与角色切换

页面上的圆形“状态”按钮可用鼠标或触屏拖到任意位置，位置自动保存；点击打开/关闭状态栏。键盘聚焦后也可用方向键移动。面板不会阻止你操作酒馆或切换角色。

窗口也可拖动：按住顶部角色名称标题栏移动，位置自动保存，重新打开和切换角色后沿用。拖动不会操作窗口内的变量，也不会触发关闭按钮。窗口会限制在屏幕范围内，缩小窗口时自动调整。

状态继续存于每张角色卡当前聊天的“状态栏”变量，角色之间互相隔离；同一卡的不同聊天也各自独立，不会把不同剧情混在一起。切换角色或聊天时，已打开的面板会重新加载对应状态，并丢弃未提交表单。未打开时，下次点击读取当前聊天状态。无角色或群聊时不显示上张卡的数据。

更新后刷新酒馆即可出现按钮。已有状态数据无需迁移。

- API 地址留空：使用酒馆当前 API 与模型连接。
- 使用独立接口：填写地址、模型 ID 和所需密钥，然后保存配置。
- 密钥仅保留在当前页面内存；刷新后需要重填，不写入角色卡、聊天变量或扩展持久设置。
- 点“生成／补充”：首次生成，已有数据只补充缺失字段。完整未修改的旧 HUD 示例会替换成角色设定。
- 点“重新生成整套”：确认后替换全部项目，操作前备份。
- 点“打开状态栏”：内置 HUD 支持项目添加/删除，以及文本、数字、布尔、列表、进度值的添加/编辑/删除。
- 点“恢复备份”：选择当前聊天的备份恢复；恢复前状态也会留一份备份。
- “取消生成”会阻止结果写入。当前酒馆连接的底层请求可能仍等待返回，并可能产生模型用量。

默认是手动生成，不会每回合自动请求模型。普通聊天生成期间请等待回复完成再使用。
内置状态栏无需小白X；之前的 HTML 前端也可继续用，两者共享本地聊天变量“状态栏”。
生成脚本不是剧情更新器：若要随剧情自动变化，启用小白X变量管理2.0并使用下面的提示词。

已有变量现在可在编辑表单中切换类型。类型切换只修改草稿，点“应用并自动保存”才写入；取消保持原值。切回之前的类型可找回该类型的未保存输入。无法明确转换成数字或布尔时需手动填写，转换为进度时需填写最大值。

## 世界书与数据

“是否读取世界书”默认勾选；“读取当前角色设定”只读取角色卡文本。主世界书、附加及可用内嵌书列在下方列表中，独立勾选才会读取，可以随时取消，不再随角色自动读取。关闭世界书总开关时不读任何书，但仍可读取角色设定与近期剧情。
从当前已启用世界书列表中勾选额外素材，不再手填书名。旧聊天/全局书选择按原设置迁移，新来源开关按角色保存，书籍选择按角色及聊天分别保存；与地图和势力概览共用读取逻辑。每次生成、重新生成及剧情更新都重新获取最新已保存正文。
无主世界书绑定时兼容角色卡内嵌世界书。只读取启用且非空的条目，但不限本轮关键词已触发的条目。
生成时不会修改角色卡或世界书文件；仅明确点击写入或同步按钮时创建／更新本插件世界书条目，不读取全部聊天记录。V1 暂不支持群聊。

不再设置素材或完整请求的字符数硬上限；不会截断或自动删减。模型/API拒绝过长请求时显示实际错误，不自动裁剪重试。
进度格式为 `{"当前":76,"最大":100}`，列表仅包含字符串。未知初始事实尽量填写“待确定”。
模型返回非法 JSON、非法变量类型，或生成期间切换聊天时，不写入生成结果。
独立剧情资料随聊天保存当前状态；每次写入前的状态进入外部存储中与楼层检查点共用的最近记录（默认 10 份，同一修订只存一次），生成状态栏时不再新增 `状态栏_生成前备份_时间戳`。在「设置 → 剧情存储」或「剧情存档」恢复最近记录；此处恢复会影响整套剧情资料。既有状态栏手工备份仍保留，可在状态栏的「恢复备份」中只恢复状态栏。0.17 的简洁存储说明见[简洁存储指南（历史参考）](../../docs/archive/STORY-CURRENT-STORAGE.md)。

独立接口支持 Chat Completions 兼容格式。基础地址例 `https://你的服务/v1`，也可填写完整 `/chat/completions` 地址。
不支持原生 Messages、Gemini 或 Responses 请求格式。接口必须允许浏览器跨域请求。
若跨域失败，将服务配置成酒馆当前连接，并把扩展 API 地址留空即可通过酒馆调用。
扩展不会读取或复制酒馆现有密钥，也不会改动当前连接设置。
所选角色卡和世界书会发给配置的模型服务。密钥不会包含在生成提示或状态变量中。

## 小白X 日常更新提示词

将以下内容放在常驻世界书条目中。不要把示例作为普通聊天消息发送。

```text
你与状态栏前端共用聊天变量“状态栏”。下面是当前真实状态：
{{xbgetvar_yaml_idx::状态栏}}
上次更新反馈：{{getvar::LWB_STATE_ERRORS}}

仅当剧情产生实际变化，在回复末尾输出 <state> 更新块，不要生成HTML。
以最新注入状态为准，只改变化的字段，不整体重写“状态栏”或恢复旧数值。
路径从“状态栏.项目”开始，保持变量原类型；保留用户添加的字段。
文本用双引号；布尔用true/false；数字不加引号；列表是字符串数组。
进度用“当前”“最大”字段，保持0≤当前≤最大且最大>0。
+N/-N表示加减，直接赋负数使用(-N)。null仅用于明确授权的删除。
冒号后留空格。没有变化就不要输出更新块。
示例仅说明格式，不得无条件照抄：
<state>
状态栏.项目.玩家.生命.当前: -10
状态栏.项目.世界.地点: "城门"
</state>
```

字段路径必须对应实际生成结果。没有“生命”等字段时，不要照抄示例路径。

## V1.11.4：前端修改与小白X恢复记录同步

前端直接写入变量后，小白X 2.0 的历史重建可能仅还原旧 state 指令，丢失未曾出现在指令中的项目。现在手动编辑、模板应用、模型生成和备份恢复会在当前末尾楼层保存小白X 2.0 完整检查点，随后增量更新以完整状态为基线。兼容层使用 stateCkptV2/version=1 格式；不支持的版本会提示错误。检查点包含当前所有变量和规则，以符合小白X全局检查点格式；不更改其他变量的值。聊天尚无消息时不能建立楼层检查点。

已经丢失的字段不会凭空补齐：更新并刷新酒馆后，在“生成设置”的恢复备份入口，可以选择生成前备份或内容完整的楼层记录恢复到当前状态。恢复会先备份当前状态，不修改聊天正文。普通浏览楼层仍不恢复变量。恢复后请再按当前剧情更新数值。

验证：使用本地保存的小白X State 2.0 执行器复现无基线时字段丢失；新增基线后验证增量更新保留未提及字段、删除/改名/类型修改与其他变量保留，以及回退不读取未来检查点。生成器和窗口页签回归通过。尚未在用户当前 TauriTavern 实例中验证。


## V1.11.5：关系数值与文字拆分后的更新规则

复制更新提示词、生成/更新数值请求、世界书更新条目共用拆分规则：已有某角色的独立好感度/亲密度字段时，分数更新到该数字或进度字段，关系文本不再添加“数字 - ”前缀；不明确的关联不猜测。不自动修改模型原始输出，也不凭空同步两个任意名称的字段。

升级后请在“设置”中再次点击“写入世界书更新提示词”，更新已经安装的条目；以前复制到聊天中的提示词不会自动改写。已被写坏的数据请在前端分别修正，之后观察下一轮输出是否更新正确路径。提示词能约束模型，但不是强制数值关联校验。

## 用户设定描述（Persona）

AI生成设置新增独立的“读取用户设定描述（Persona）”，默认关闭。勾选后，生成/补充、重生成和剧情更新每次读取当前用户名称及Persona描述，不自动读取角色或世界书，不截断描述。描述为空时提示补充或关闭选项，不用角色卡代替。生成期间修改所使用的用户设定会使结果失效，避免写入过期结果。此来源只作背景素材，不能授权更改字段类型。

## 项目重命名与变量转移

进入编辑模式后，项目标题旁的“重命名”可修改项目名称；变量下方的“转移到…”可选择已有目标项目。转移保留值与类型，源项目即使变空也保留。目标名称、变量或规则冲突时会拒绝覆盖。

两项操作同步迁移小白变量 2.0 的对应规则路径，并沿用当前楼层保存与外置状态归档流程；旧楼层快照保持原名和原位置。自定义提示词、世界书正文等自由文本中的旧路径需要自行修改。
