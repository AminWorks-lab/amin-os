# 0.18 独立剧情资料

Amin 的人物、背包、关系、场景、世界状态等应用共用当前聊天的一份剧情状态。无需小白变量引擎，也不会在切换楼层、Swipe 或删除消息时回放以前的变量。

## 当前资料与备份

当前唯一资料位于 `chatMetadata.amin_os_state_v1`，包含版本、修订、保存时间和类型明确的模块快照。当前资料随酒馆聊天保存与同步，不另建外部当前副本。Amin 不会从旧应用历史、旧索引或原生变量自动回退取值。

兼容的 TauriTavern 扩展文件接口只用于命名存档、最近记录（操作前备份、恢复前备份与楼层检查点共用，默认 10 份，同一修订只存一次）及原始旧资料归档；聊天元数据只保留这些记录的引用。备份按聊天身份隔离，记录通过内容校验，写入前比较已有记录、写入后回读核验；这些检查不能保证宿主的跨设备并发写入具有原子性。数量有上限，资料本身增长仍会增加占用。

没有外部接口时，当前资料仍可随聊天保存，也能导入和导出 JSON；外部最近备份不可用；剧情存档的命名存档留在聊天内，完整检查点最多保留 2 份。清空前可先点击「导出当前剧情备份」。跨设备需要同步聊天；如需保留外部最近备份和原件归档，还需同步宿主扩展存储，或分别导出需要保留的资料。

## 旧聊天第一次使用

更新插件后刷新酒馆，在 **存档与历史 → 剧情存储** 选择以下流程。打开页面、选择来源及预览均不会自动迁移。

1. 选择「当前应用中的旧资料」，或「小白变量 2.0 中的旧资料」。后一项只读取目前存在的原生变量，不重放任何旧楼层。
2. 点击「预览导入旧资料」，核对各模块数量、错误、缺失引用和默认值说明。
3. 预览有效后点击「确认应用预览」，建立或替换当前 Amin 状态。

重复人物或其他实体编号会拒绝导入，插件不会猜测哪个记录正确，也不会自动重新编号或去重。旧应用派生历史损坏、当前原生变量仍有效时，可以明确选择原生变量来源；若两种来源都不能确认，使用「开始空白剧情资料」，随后重新生成或登记资料。

原生旧快照可能没有完整保存应用偏好。例如场景的时段或读取设置缺失时，预览会说明使用哪些模块默认值；已有原件不会被这些默认值改写。不能把某个旧楼层的状态猜成当前资料。

导入 JSON 时，点击「预览导入剧情备份」，选文件并核对预览，再确认应用。支持独立剧情 JSON、可验证的旧当前状态备份及既有 Amin 命名存档；旧楼层图备份不能直接猜测为当前状态。聊天、候选或来源变化后，预览作废，需要重新检查。

## 原始旧资料怎样保留

首次应用前，退出使用的旧应用事件根会先保留完整原件，包括其中损坏或重复的数据；原件归档不执行类型修复或去重。

- 外部接口可用：在独立原件表按聊天身份保存第一份归档。相同内容重复提交不新增文件，不同内容不会覆盖既有原件。
- 外部接口不可用：在聊天元数据 `amin_os_legacy_source_v1` 保存一份静态源，不再作为活动剧情资料读取，后续操作不会继续追加旧事件。

「导出旧资料原件」可以下载这份原始资料。聊天正文、原生变量、原生 WAL／检查点和旧外置历史文件保留；Amin 不再执行它们。能力库、世界书和 API 配置也保留。原件导出用于留存与核对，不等同于把损坏数据自动导入为有效当前状态。

## 清空与恢复

「备份并清空当前资料」只重置当前聊天的 Amin 剧情资料，保留正文、全局能力库、API 设置、世界书和原始旧资料。没有外部接口时，按钮会显示「清空当前资料重新生成」，页面会说明本次不能新增最近自动备份；可以先手动导出 JSON。

恢复时点击「查看最近备份」，选择记录，再「预览所选备份」。核对后点击「确认应用预览」才替换当前资料；查看或选中备份不会自动恢复。恢复不会回退酒馆消息或回复候选。

库存账本、信息修改前后记录和剧情档案草稿属于实际业务资料，正常保存继续保留。去掉的是逐楼层状态回放，不会把这些记录当成冗余缓存清空。明确重置相应资料时，才按该操作的范围清空。

## AI 联动与手动编辑

在 **联动更新**（首页磁贴，世界状态中也有“打开联动设置”） 为各模块设置参与联动、提供资料与允许更新，选择审核或自动应用。插件将当前资料和协议插入模型上下文，不改写已发送正文，也不依赖世界书触发或小白执行 `<state>`。

模型使用完整 `<amin_update>...</amin_update>` JSON 块提交类型化操作。新人物等实体使用 `@new:alias` 临时别名，最终稳定 UUID 由插件分配；同批引用使用对应别名。已有实体必须使用已有 ID，不能按同名人物自动重连。

完成独立资料初始化后，插件内部更新提示词使用新协议。已有世界书原文不会被批量改写；旧 Amin 管理的更新条目在本轮扫描中屏蔽，新协议由插件直接提供，不需要重新安装世界书条目。独立模式的更新规则预览和复制显示实际提供的规则，不合并旧条目的手写前后文。希望保留的数值或剧情业务规则可放入联动页「用户补充要求」，去掉旧 `<state>` 路径格式说明。其他手写世界书或预设中的旧格式要求不会被插件自动更改，需由你停用或调整。

整组更新需通过格式、模块权限、实体编号和引用校验，任一项失败则整组拒绝。审核模式需确认，自动模式也经过相同校验。模型不能通过更新块修改聊天正文、API、世界书、全局能力库或插件权限。

保存失败后，只重试已确认结果的持久化，不重新执行扣除、转交、旅行、推进时钟或能力发动。旧「直接发动」效果如果实际仍有目标，按有目标记录兼容并保留目标；真正无目标的新直接发动定义保持不变。

## 隐藏正文中的更新块

在酒馆正则中新建规则，查找表达式填写：

```regex
/<amin_update>[\s\S]*?<\/amin_update>/g
```

替换文本留空，作用位置选择 **AI 输出**，启用 **仅格式显示 / Alter Chat Display**。这只隐藏显示，保留聊天原文供 Amin 读取更新块；不要将更新块从消息原文中删除。若希望后续发送给模型的历史正文也不显示更新代码，可同时启用 **仅格式提示词 / Alter Outgoing Prompt**。最小、最大深度留空即可作用于所有楼层。

这条规则只处理 `<amin_update>`，不处理其他插件的 `<state>` 块。

## 验证边界

自动回归使用真实应用模型和服务，在模拟宿主上下文及内存／模拟文件接口中检查读写、预览、重复编号拒绝、整组更新、失败重试、备份和跨聊天竞态；静态检查确认源码可解析。它们不等于用户实际 Android、手机触控、酒馆事件时序、跨设备同步或模型供应方已经验收。

旧文档中的 `<state>`、楼层索引恢复和外部当前变量副本属于 0.16–0.17 的历史结构。0.18 的操作以本指南及当前页面为准。
