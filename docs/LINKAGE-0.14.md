# 0.14 · 统一关联与剧情更新

> 以下保留旧版方案。0.16 起日常剧情已改为小白 X 原生 `<state>` 变量更新，请先阅读 [0.16 迁移指南（历史参考）](archive/STATE2-0.16.md)。

这版继续扩展现有应用。人物数字仍由世界状态管理；物品归背包，地点归地图，事实归剧情档案。关联使用稳定 ID，修改名称不会改绑到同名对象。

## 开始使用

1. 更新并刷新扩展，在世界状态中打开“联动更新”。OS 窗口与最新消息楼层都能进入。
2. 勾选启用统一联动，检查参与的模块。已有资料会出现在模块列表中，也能为尚无资料的模块手动启用。
3. 每个模块分别设置参与、允许读取和允许更新。允许更新需同时允许读取；骰子始终只读。隐藏磁贴不改变这些设置。
4. 先用“预览确认”模式；需要时可以选择校验通过后自动应用。保存设置后，分别查看世界书规则和“消息内资料预览”。
5. 将统一条目安装到当前聊天世界书或角色主世界书。条目名称为 **Amin OS · 剧情状态更新**，保留且只保留一个 `{{amin_os_linkage}}` 占位。
6. 正常发送剧情。模型应在正文后返回一个更新块；没有可提交变化时返回 `<amin_update>{"version":1,"changes":[]}</amin_update>`，插件只提示无变化，不保存资料。收到 `<amin_update>` 时，到联动更新查看各应用的变更，一次确认保存。出错或资料变化后，整批拒绝，不只执行其中一部分。

世界书条目只持久保存模板。生成时只在酒馆本次扫描副本中展开启用模块的变量更新协议与规则，不包含当前资料。人物、背包、场景等资料和引用目录由插件通过扩展提示插入 AI 消息上下文；不修改可见聊天正文或历史消息。仅需读取资料时无需安装更新世界书。可在世界书编辑器调整位置、触发条件和占位前后的补充规则；重复安装会保留这些修改。联动页的额外要求按聊天保存。

## 哪些资料会参与

| 模块 | 参与方式 |
| --- | --- |
| 人物卡 | 身份、外观、属性绑定；数值仍更新世界状态 |
| 世界状态 | 现有字段的类型安全更新，支持数值与进度分量 |
| 背包与账本 | 物品、穿戴、状态、消耗、转交、资源收支，保留账目 |
| 人物关系 | 有向关系及来源、阈值规则/提醒 |
| 场景与时间 | 时钟、场景、实际在场、NPC 作息及已配置的离场规则 |
| 剧情档案 | 事实、记忆、伏笔；编年史模型更新先成为草稿 |
| 能力面板 | 聊天内生效记录、叠加与周期结算；全局能力库不由模型修改 |
| 地图 | 已有地图内可访问的地点、道路及当前位置 |
| 势力概览 | 尊重已有字段锁定的局部更新 |
| 信息面板 | 已确认内容及字段更新；未知/推断值不冒充事实 |
| 骰子 | 仅已发送且与当前聊天匹配的固定结果，不让模型重新掷骰 |

存档负责保存这些资料；世界书管理负责选择资料来源；回复/改写通过所选 AI 渠道读取统一上下文；语音与外观设置保留自身用途。剧情更新不能修改 API 密钥、全局配置、聊天正文或固定骰点。

“参与联动”是这套机制的模块开关。未参与的应用仍可手动打开使用；它们原来的单独更新方式保留。已参与的模块会停止重复的旧规则注入。用户自己编写、没有 Amin 所有标记的世界书条目不会被自动禁用。

## 关联与一致性

关联页列出人物属性绑定、物品持有人、关系双方、记忆知情人、日程地点和效果结算对象。来源和目标下拉可以为其他条目补充手动关联。删除手动关联只解除链接，不删除条目；程序推导的关系由所属应用维护。

模型更新先在副本上执行，验证全部动作与引用，再用一次元数据提交写入。创建人物后转交物品、喝药后恢复生命等关联动作应放入同一个 `changes` 数组。模型无权修改未允许更新的模块；能力周期结算若涉及背包与世界状态，也需要相应模块的更新权限。

已有的缺失引用会显示出来，不会自动按名称修复。模型提交的新悬空引用会被拒绝。手动删除人物后保留其资产/历史的既有行为仍可使用，随后可在相应应用明确修复。

重复事件与保存重试不会再次扣数值、转交、推进时间或结算。聊天、回复候选、正文或依赖资料在生成/预览期间变化时，旧建议失效。变量更新同时保存适用的小白 State 2.0 检查点；其他变量与规则保留。

## 新功能入口

- **剧情档案**：事实与记忆、自动整理、前作引用。事实和人物对事实的认知分别记录；传闻与遗忘不删除原事实。自动整理默认关闭，生成草稿后仍需确认，前作引用需明确选择。
- **人物卡**：整体外观与发型，实时查看背包穿戴，并进入该人物的关系、记忆、日程、资产。
- **背包与账本**：衣物部位与层次，湿润、污渍、破损程度。指定部位的衣物逐件登记，同人物同部位同层次避免重复穿戴。
- **场景与时间**：NPC 日程、已确认在场、活动耗时、自定义固定月长历法、离场规则及楼层时间。预计活动不强制改变人物位置，时间变化不自动结算离场影响。
- **人物关系**：剧情更新建议和阈值提醒。提醒是已知数值变化的记录，不自行生成剧情行为。
- **能力面板**：叠加方式与周期结算。先预览属性、资源和物品影响，再确认；读取面板、注入提示和推进时钟都不会暗中扣数值。
- **跨应用存档**：自动完整楼层检查点、已有检查点的新建分支。历史楼层没有完整检查点时不会从未来状态推算。创建分支成功但恢复保存失败时，在新分支重试保存即可，无需重复分支。

## 酒馆渠道与预设

“酒馆当前配置 · 完整预设”由酒馆按 Quiet 规则组装任务上下文。Amin 工具任务自带同一份只读投影时，会抑制 Quiet 中的重复资料注入及更新规则。指定连接配置及独立 API 使用 Amin 组装的同一资料。

普通剧情更新只接收本次实际激活统一条目后得到的完整新回复；继续生成和 Quiet 只读，不自动结算。最终预设是否包含世界书位置、宿主版本是否支持所需事件，应在实际酒馆里检查请求。

知情规则用于区分旁白事实和人物认知；其他世界书、历史聊天仍可能包含相关信息，因此不能保证模型完全不知道秘密。当前完成源码、自动测试及隔离浏览器验证；实际酒馆、供应方返回和物理手机需另行验证。
