# 0.16 · 小白 X 变量 2.0 接入

> **历史参考。** 本文描述的存储或运行时已在 0.18 移除，现行代码不再执行；仅保留用于理解和导入旧聊天资料。现行说明见[独立剧情状态指南](../INDEPENDENT-STORY-STATE.md)。

## 数据与执行

日常剧情回复只使用小白 X 的 `<state>` 格式。小白负责执行、记录楼层与重放；Amin OS 提供变量路径说明、消息内资料和各应用窗口。Amin 不会再次执行同一条 `<state>`。

世界书只放变量更新规则。当前人物、背包、关系、场景、记忆、地图等资料仍由插件插入 AI 消息上下文，不写入可见聊天正文。

小白保存变量不等于自动把所有变量发给 AI。默认由 Amin 发送勾选的当前资料；若预设或世界书已用 `{{xbgetvar_yaml_idx::变量名}}` 等宏提供这些资料，可把“资料发送来源”改成“预设／世界书自行提供”，关闭 Amin 的重复注入。独立 API 工具请求也遵守这一选择，需自行选择足够的资料来源。

原来的 `<amin_update>` 只用于兼容旧建议和手动 AI 生成资料的内部校验，不再是日常剧情的输出协议。联动页的旧“预览后确认/自动应用”不再控制小白原生变量更新。

## 迁移

1. 在小白 X 启用变量管理并选择 **2.0**，刷新扩展。
2. 打开 Amin OS → 世界状态 → 联动更新，检查当前聊天的模块参与、读取和更新设置并保存。
3. 点击 **初始化／迁移剧情变量**。已启用联动的聊天在首次剧情生成前也会尝试迁移；遇到已有变量冲突则停止并提示。
4. 在“消息内资料预览”核对变量路径，再正常生成剧情。

迁移保留旧应用数据和迁移备份。变量成为权威的当前状态；旧 metadata 仅作为兼容窗口和历史的派生数据，不会在变量回退后自动覆盖变量。不要同时启用多份 Amin OS。

## 变量根

| 内容 | 根变量 |
| --- | --- |
| 世界状态 | `状态栏`（沿用原变量） |
| 势力资料 | `势力资料`（沿用原变量） |
| 人物与外观 | `AminOS人物` |
| 背包与账本 | `AminOS背包` |
| 人物关系 | `AminOS关系` |
| 场景、时间与日程 | `AminOS场景` |
| 剧情档案与记忆 | `AminOS剧情` |
| 持续效果 | `AminOS效果` |
| 地图 | `AminOS地图` |
| 信息面板 | `AminOS信息` |
| 固定骰点 | `AminOS骰子`（只允许骰子应用写入；原生守卫限制见下文） |

API 渠道、主题、全局能力库和应用配置仍由用户设置管理。引用继续使用稳定 ID；数组操作必须依据消息资料给出的真实变量路径，不能把过滤后预览的序号当成原数组序号。

场景的日历与自动规则、关系阈值设置、信息归档库等仍保留为应用配置或独立归档；当前剧情日程与当前信息记录进入变量。新建剧情档案先保存为未启用的待核对记录，真实聊天来源必须在应用中绑定后启用，AI 不应编造来源标记。

## 世界状态示例

当这两个文本字段已经存在且剧情确有对应变化时：

```text
<state>
状态栏.项目.HK416.心智状态: "完全解锁（心智私密模块完全开放）"
状态栏.项目.德尔.当前状态: "全面浏览并掌控HK416的心智私密模块"
</state>
```

冒号后留空格；字符串加双引号。数值 `+N/-N` 为增减，负数赋值用 `(-N)`。更新错误以小白的 `LWB_STATE_ERRORS` 为准；应用结构或引用不合法时，Amin 会报告同步失败，不悄悄用旧值覆盖变量。

## 手动编辑与楼层

从 **0.16.2** 起，已迁移聊天切换分支时，Amin 调用当前已加载小白扩展的原生楼层回放，完成后才刷新应用和记录历史。恢复期间暂停手动写入；找不到小白入口、存在多份安装或回放失败时显示错误，不把复制来的较新变量当作已恢复状态。普通向上滚动或查看旧楼层窗口属于浏览，不会修改当前剧情变量。

该桥接通过小白公开回放接口（若提供），或已加载的同源 LittleWhiteBox／Xiaobai 扩展脚本定位原生模块。恢复目标是当前分支的最后一楼。没有检查点或更新日志的旧楼层无法恢复未记录的数据，首次迁移也不会补造过去的剧情状态。

各应用的手动保存同时更新对应变量和当前楼层基线，避免下一次正常生成恢复旧值。部分小白分支在回退到较早楼层时会废弃未来检查点；未来楼层中仅手动保存、没有聊天 `<state>` 记录的变化不会凭空重放。这沿用小白回退语义，重要手动修改可另外保存跨应用存档。

适配依赖小白当前 State 2.0 日志/检查点版本；遇到未知格式停止迁移。为新变量根登记独立的初始化所有权记录，不改写已有消息的更新操作。验证包含原生引擎级测试，但不等于已在用户的实际宿主、模型和手机上验收。

本次原生引擎验证使用上游 **3.1.5 / a2b39f7**：迁移前后回放、分支隔离、手动保存和重复消息执行通过。历史 fork `1492659` 会删除未来检查点，回退到迁移前再前进无法恢复迁移基线。

当前上游的只读守卫仍允许用 `null` 删除骰子嵌套字段。Amin 检测到此类操作会拒绝同步并保留应用中的原骰点记录，但原生变量已经被改变，需要在小白中修正错误更新并重放。Amin 不会另行执行一次恢复指令覆盖分支状态。原生更新也可能部分成功；请以小白的错误反馈和实际变量为准。

参考：[官方变量 2.0 文档](https://docs.littlewhitebox.qzz.io/数据互动/变量管理2.0)。

## 通用联动范围模板

在“联动更新 → 联动范围与更新权限”选好模块并保存，然后点击“将已保存范围设为通用模板”。模板保存在酒馆的扩展设置中，包含联动总开关和每个模块的启用、读取、更新权限。

未单独保存联动设置的聊天（包括未配置的旧聊天）自动采用通用模板；修改通用模板也会影响这些聊天。保存过独立联动设置的聊天优先使用自己的配置；分支继承原聊天配置。需要给已有聊天换用模板时，点击“将通用模板载入当前草稿”，检查后保存即可。

模板不携带剧情资料、额外规则、手动关联、更新记录、资料预算或固定条目 ID，也不会自动绑定世界书。新聊天仍需绑定包含统一条目的世界书。模板通过宿主 saveSettingsDebounced 保存；宿主返回的错误会回滚本次内存修改，防抖接口不提供磁盘落盘确认时无法额外保证落盘完成。
