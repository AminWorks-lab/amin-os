# 旧模式：剧情文件存储与跨设备同步

> **历史参考。** 本文描述的存储或运行时已在 0.18 移除，现行代码不再执行；仅保留用于理解和导入旧聊天资料。现行说明见[独立剧情状态指南](../INDEPENDENT-STORY-STATE.md)。

本文描述 0.17.0 引入的旧楼层／Swipe 索引模式。0.17.4 新聊天默认使用 [当前变量与最近五份备份](STORY-CURRENT-STORAGE.md)，旧索引聊天需显式切换。下文中的「文件模式／新模式」指旧索引实现；只有继续使用该模式时才需要历史文件与候选标识修复步骤。

## 使用方式

在 **Amin OS → 外观设置 → 剧情存储** 中查看当前聊天的存储模式。TauriTavern 文件接口可用且聊天最多只有一条消息时，首次迁移到小白变量 2.0 会自动启用新模式；也可以点击「为当前聊天启用文件存储」手动启动。原有楼层记录、变量和聊天文件不会自动删除。已有较长聊天继续按旧模式读取，不能在中途切换新模式。

新模式把 Amin 自己新增的历史记录写成短小的消息引用。剧情状态本身按内容去重写入 TauriTavern 的 `api.extension.store`，使用检查点和差量记录；若写入或校验失败，不应生成指向缺失文件的引用。小白 X 变量 2.0 仍负责当前聊天变量与 `<state>` 的执行，文件记录用于旧楼层查看和分支的历史状态。

小白 X 原生的变量、楼层日志与写入记录仍属于聊天元数据。文件模式不会把这些原生数据移到外部，因此聊天文件不可能只剩状态 ID。OS 的占用统计只在点击「统计当前聊天占用」后扫描当前聊天引用的文件；它不是后台定时扫描。显示的是引用文件的 JSON 内容估算量，不等于 TauriTavern 的全部同步传输量。

## 电脑与手机同步

在 TauriTavern 的同步范围中，同时包含：

1. 对应的角色聊天历史或群聊历史。
2. 扩展存储 `extensions.store`（同步范围的「Extensions / Extension store」）。

两个数据集缺一不可。只有聊天文件时，楼层里的状态引用无法加载；只有扩展文件时，无法确定状态对应哪条消息。同步完成后先确认两端都收到文件，再从旧楼层打开历史或继续分支。同步范围是由 TauriTavern 管理的，Amin 不会通过浏览器缓存保存一份替代数据。

需要手动转移时，先在源设备导出当前聊天的剧情备份，同时备份相应聊天文件；在目标设备导入剧情备份并放回同一聊天。导入先校验文件和引用，再补齐缺失记录；它不会自动切换聊天或覆盖当前小白变量。通过同一设备的导出／导入，可以检查存储文件是否完整，但这不能代替另一设备的实际同步验证。

如果楼层变量尚未恢复，仍可在剧情存储页使用「导入剧情备份文件」，补齐外置文件后点击同页的「重试恢复当前分支」。页面显示具体失败原因；「刷新状态」只刷新显示，不执行恢复。导入本身不改写当前变量，重试恢复才会把当前分支的末楼状态恢复到变量。聊天切换或候选变化会取消操作，生成及保存期间不能重试恢复。

## Swipe 标识重复或缺失的恢复

剧情备份 JSON 包含外置索引和状态文件，但不包含所有候选正文。导入成功后仍报「重复 Swipe 标识」或「已有存档的 Swipe 稳定标识缺失」时，需要保留完整标识的原聊天 JSONL 作为证据。

1. 打开报错的聊天，确认插件已更新至 0.17.3 或以上。在 **设置 → 剧情存储** 导入该聊天的剧情备份 JSON，补齐外置文件。
2. 点击「用原聊天校验 Swipe 标识」，选择原聊天 JSONL。这只读取文件，不会把原聊天导入酒馆或替换当前正文。
3. 核对「Swipe 标识修复预览」的楼层、候选、原标识、恢复标识和原状态文件。点击「应用标识修复」保存核实的标识。
4. 点击「重试恢复当前分支」。这一步才读取当前末楼对应的原存档并恢复小白变量。恢复成功后可以继续生成或切换回复候选。

校验要求同一稳定消息标识、同样的说话者及正文、唯一的候选匹配、原始与当前索引中的有效关联，以及完整的状态文件。候选重排不影响通过标识查找的原状态。若原聊天也缺少标识、正文无法对应或存在相同的候选正文，会停止修复并显示原因；不能仅凭楼层或 Swipe 编号确定归属。

标识修复不会重建正文、剧情状态或规则，也不会将当前变量写入旧候选。保存失败时尝试撤销此次标识改动；若聊天或候选已经变化，拒绝过期回滚并保留原始保存错误，应返回原聊天重新校验。操作期间请等待保存结束再切换聊天。原聊天 JSONL 和剧情备份 JSON 应一起保留。

## 保留与清理

删除旧聊天由用户自行决定。Amin 不自动删除旧楼层数据，不自动清理外置状态文件，也不把未确认可达性的文件视作垃圾。不同分支可能引用同一状态；仅凭单条聊天的引用无法安全判断某个文件是否还能删除。

旧聊天可能仍有历史记录中的重复元数据。已有较长聊天不会自动迁移；启用新模式也不会直接缩小已经保存到聊天文件里的小白原生变量和日志。用户若决定删除旧聊天，应先确认需要保留的剧情资料与分支已经备份。

## 故障提示

- **扩展文件存储不可用**：确认使用支持 `api.extension.store` 的 TauriTavern 版本；当前实现不会回退到聊天元数据或本地浏览器缓存，以免产生无法跨设备读取的引用。
- **引用文件不存在**：确认另一设备同步了 `extensions.store`；必要时从源设备导出该聊天的剧情备份并在目标设备导入。
- **Swipe 标识重复或缺失**：按照上方步骤用原聊天校验和修复。备份导入不自动改动消息中的候选标识。
- **聊天在操作时切换**：重新打开目标聊天并重试。导出、导入和启用操作都以操作开始时的聊天为准。
- **同步传输量仍大**：检查所选同步范围和现存旧聊天、聊天备份及媒体文件。新存储控制后续剧情记录的重复写入，不会立即缩小宿主已有文件。
