# 全库剧情存储分析

> **历史参考。** 本文描述的存储或运行时已在 0.18 移除，现行代码不再执行；仅保留用于理解和导入旧聊天资料。现行说明见[独立剧情状态指南](../INDEPENDENT-STORY-STATE.md)。

入口：设置 → 剧情存储 → 全库剧情存储分析。

点击“扫描全库剧情文件”后才读取资料，不在后台自动扫描，不把报告写入聊天。支持取消；关闭面板会取消并丢弃迟到的结果。

## 报告能回答什么

- 已读取聊天正文与备份响应的逻辑大小；备份由 TT 解压后读取。
- Amin `amin-os/story-v2` 表中可识别外置文件的 JSON 估算大小。
- 每份聊天／分支／备份引用的外置依赖，区分独占和共享。共享文件全局只计一次，不能累加每行共享占用。
- 当前可枚举范围内未发现引用的文件。可明确展开预览，重新核验后下载原始文件备份。
- 未知文件、损坏、缺失引用、读取失败及上限中断。

这些大小不是磁盘压缩后占用，也不是实际同步传输量。报告不统计图片、媒体和其他扩展，不能直接用它断言全部 600 MB 同步来自 Amin。

已验证的内容寻址文件按内容 ID 复用；不根据名字猜测重复文件、不自动合并。

## 当前为什么不提供永久删除

核对 TauriTavern v2.3.0（a1855be）的公开 API 后，有两项尚不能证明：

1. 角色与群组目录能枚举注册聊天及其分支，但无法保证包含删除角色后留下的目录。全局聊天搜索会省略读取所需的角色标识。
2. 没有覆盖聊天保存、扩展文件写入及跨设备同步的公开全局维护锁。顺序扫描或扫描两次都不能代替原子一致性保障。

因此“注册目录读取完成”不等于全磁盘覆盖，也不等于文件可以删除。当前界面明确标记覆盖不足，保留观察到的占用和未引用候选，不调用任何删除 API。这是分析与清理预览工具，尚不是垃圾回收器。

后续永久清理需要宿主提供完整目录枚举和维护事务，或设计另经验证的离线清理流程。不能直接放开按钮绕过这些条件。

## 扫描与导出边界

默认最多读取 10000 份聊天／备份、每个响应 64 MiB、合计 256 MiB；外置记录最多 50000 个、256 MiB JSON。超限停止并报告部分扫描，已显示量只代表已扫描部分。

每份聊天完成校验与指纹计算后仅累计所需引用，正文、Swipe 文本和变量大对象不会跨文件保留；运行入口按顺序扫描外置文件并分批让出界面执行。

所有楼层的 Swipe、旧引用的 parentStateId、聊天索引全部候选、分支继承索引、差量父文件、marker 中的备份引用均被追踪。文件经过已有图格式及 SHA 校验，未知旧格式保守阻止清理资格。

候选导出前会重新扫描并比较指纹，再逐份核对文件内容。下载 `amin-os-story-library-archive` 原始文件集合（最大 64 MiB）不会移走或删除原文件；它不是“导入当前聊天剧情备份”所接受的单聊天包。

## 验证范围

有模拟 host API、引用闭包、共享计数、取消、上限、变化后拒绝导出和窄屏 UI 测试。没有读取用户真实聊天，也没有真实手机／跨设备同步性能测量。
