# 旧模式：剧情存储的聊天索引与 Swipe

> **历史参考。** 本文描述的存储或运行时已在 0.18 移除，现行代码不再执行；仅保留用于理解和导入旧聊天资料。现行说明见[独立剧情状态指南](../INDEPENDENT-STORY-STATE.md)。

本文仅描述旧 `story-v2` 索引模式。0.17.4 新聊天默认采用 [当前变量与最近五份备份](STORY-CURRENT-STORAGE.md)，不保存逐楼层或逐 Swipe 状态；已有旧索引聊天仍可继续使用本文结构，或明确切换为简洁存储。切换不会自动删除旧索引及共享外置文件。

## 当前结构

- 聊天元数据 `amin_os_story_storage_v2` 保存起始状态、备份入口和当前 `indexId`。
- 每条消息保存稳定的 `amin_story_message_id`，每个 Swipe 的 extra 保存 `amin_story_candidate_id`。正文编辑不会更换这些标识。
- 外置索引按聊天身份保存楼层顺序、消息标识、选中的 Swipe，以及各 Swipe 的状态文件编号。
- 索引和变量状态均存入 TT 扩展存储 `amin-os / story-v2`。文件不可变，支持差量与内容复用；聊天只更新索引入口。
- 小白变量 2.0 中仍有当前运行所需的变量。历史状态不再重复写入每条消息。

## 分支、回退与修改

创建分支后复制过来的消息保留稳定标识。插件根据新聊天实际保留的消息与 Swipe，生成独立索引并记录来源索引。历史变量文件共用，后续写入不会修改原聊天索引。来源聊天后来改变也不会改变已建立的分支。

删除、插入、移动楼层时重新排列索引，恢复按消息标识和当前 Swipe 找到原有记录。用户／系统消息若尚无状态则沿用之前的状态。插入未知 AI 消息、缺失文件或重复标识时停止恢复，不按相同楼层数字猜测。

正文编辑保留原有状态，不自动推断新的变量。若编辑改变了剧情，需要用户修改变量，或通过新的生成更新变量。生成期间暂停归档，完成后再保存；未完成的新 Swipe 不得读取旧候选的存档。

## 旧记录迁移与备份

打开已有外置存储聊天时自动迁移：读取各候选原引用，验证对应状态文件，写入索引后才用稳定标识替换消息中的旧指针。迁移不根据正文重新推断状态，也不将当前最新变量灌入历史楼层。旧引用的正文哈希失配不再阻止迁移；原记录本来就错误的状态仍需要人工核对。

实际文件写入失败、文件缺失或操作期间切换聊天，都会停止关联。异步保存仍检查操作期间上下文是否改变；这与长期使用正文哈希判定存档有效性不同。

剧情备份包含当前索引和可达状态文件。跨设备还需同步相应聊天文件以及 TT 的扩展存储。只同步聊天无法恢复外置数据。

已有索引时，缺失的历史候选标识不能重新编号。首次延迟形成候选列表时，仅允许单一已保存候选将自身标识补入第一个 Swipe；不能借用当前选中的另一候选标识。

0.17.3 提供原聊天 JSONL 的只读校验：待修复消息通过稳定消息标识定位，候选按完整说话者／正文的唯一哈希匹配原候选，再确认原始索引与当前索引均含该标识。当前候选位置可以不同，状态归属始终按标识读取。原标识缺失、重复或正文存在歧义时拒绝修复。

修复方案只保留在内存中，绑定当前聊天、候选、标识、引用及索引，不能通过序列化伪造。显式应用只写入候选标识和当前候选镜像，保存前再次同步复核；正文、存档文件及当前变量不变。保存后需显式重试恢复，避免将未恢复的当前变量误归档。候选变化或聊天切换会使方案失效，另一聊天的恢复状态不会被旧操作覆盖。

历史不可变索引也使用差量，按需写入；重复读取和无变化保存不生成新版本。当前没有自动删除全局外置存档文件，避免删掉仍被其他分支引用的文件。删除聊天不会自动回收所有相关文件。

## 保存与读取优化

- 自动归档完成后，可向紧接着的宿主保存传递一次性准备凭证。凭证仅在内存中，绑定聊天、完整候选信息、引用、当前剧情变量与规则；符合时省去重复捕获，变量变化则重新准备，聊天或候选变化则拒绝关联。全部保存准备完成后再同步复核，防止其他准备步骤使先前结果失效。失败重试重新校验，不复用已消费凭证。
- 外置归档后宿主聊天保存失败，会保留绑定原聊天元数据与身份的待保存标记；之后普通生成前或变量更新事件触发归档时，即使状态没有变化，也会重新提交宿主保存。成功后清除标记；无变化的定时检查不反复尝试磁盘写入。标记仅存在本次运行内，关闭页面前仍需处理保存失败提示。
- 构建聊天索引仍扫描消息／候选身份，但只复制需要更新的消息与索引行。末尾消息及其候选行始终单独复制；新增、旧引用迁移、Swipe 变动走重建流程。楼层顺序继续按当前聊天重建，所以删楼、移动和分支不依赖旧楼层数字。
- 迁移与历史完整性检查通过 `visitMany` 顺序读取多个状态，同一次操作共享已经校验的父链。缓存最多保留 64 个节点，状态与文件的序列化 UTF-8 合计预算不超过 32 MiB；这不是 JavaScript 堆内存上限。超预算节点正常读取但不缓存，操作结束释放，下一次操作重新读取。错误不会变成可用状态，检查页仍逐项报告缺失／损坏记录。

这些优化不改变文件格式或消息标识，不需要迁移存档。哈希、父链、聊天切换、变量变化以及写入后校验继续执行。实际设备耗时需在 TauriTavern 中测量，自动测试的复制／读取次数不代表设备提速倍数。

## 验证范围

自动化覆盖正文修改、旧引用迁移、历史分支隔离、楼层插入／删除、Swipe 重排／删除／复制、原聊天校验与标识修复、跨设备导入、文件缺失、保存失败及异步聊天切换。实际 TauriTavern 设备上的生成与同步仍需验证。
