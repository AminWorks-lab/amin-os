# Amin OS 统一 UI 规范

版本：UI v2 · Amin OS 0.13 · 2026-09-23

适用范围：本轮重做后的主窗口、全部应用、楼层窗口与世界状态 iframe。
本规范记录代码中的实现约定。实施与验证边界见第 9 节；实际酒馆与真机仍待验证。

## 1. 设计原则

沿用现有主题颜色与用户外观覆盖，统一布局、控件尺寸、间距和反馈。窗口标题、当前数据范围、操作、正文之间建立清楚的层次；地图、状态字段、回复候选和骰子结果保留适合业务的展示方式。

普通应用采用「当前上下文 → 可选分类导航 → 操作区 → 内容卡片 → 可选保存区」。窗口头部显示应用名，页内上下文保持紧凑。数据作用范围需要直接说明，例如“当前聊天”“当前剧情状态”“本楼历史快照”“跨聊天预设”。

## 2. 主题变量

外观配置由 `settings/appearance.js` 统一解析；应用独立设置优先于全局设置。现有主题为：Windows 10 浅色、Windows 10 深色、薄荷夜色、深海蓝、旅人纸页、樱花物语、夜色紫晶、极简墨白。

| Token | 使用位置 |
| --- | --- |
| `--amin-bg` | 窗口和页面底色 |
| `--amin-card` | 内容卡片与提示背景 |
| `--amin-control` | 输入框、次要按钮与原文预览 |
| `--amin-text` / `--amin-muted` | 正文 / 次要说明 |
| `--amin-line` | 边框、分隔线 |
| `--amin-accent` | 主按钮、选中边框、结果强调 |
| `--amin-ink` | 主按钮在强调色背景上的文字 |
| `--amin-accent-text` | 强调文字；Windows 主题按可读性使用正文色 |
| `--amin-font` / `--amin-radius` | 基础字号 / 圆角 |
| `--amin-gap` / `--amin-space` | 用户密度间距 / 组件实际间距 |
| `--amin-opacity` / `--amin-blur` | 窗口透明度 / 背景模糊 |
| `--amin-floor-width` / `--amin-floor-height` | 楼层窗口桌面宽度 / 当前设备使用的高度 |
| `--amin-floor-desktop` / `--amin-floor-mobile` | 两类设备的楼层窗口高度配置 |

正文统一使用 Segoe UI、Microsoft YaHei、sans-serif；品牌保留本地 Courgette 字体。业务应用不另建固定深色配色。Windows 桌面风格、自定义背景和磁贴效果继续由各自配置控制。

## 3. 尺寸与响应式

| 项目 | 当前代码约定 |
| --- | --- |
| 默认字号 | 13px；用户可设 11–20px |
| 正文 / 控件行高 | 通常 1.6 / 1.5 |
| 默认圆角 | 14px；用户可设 0–24px；Windows 外形保留直角 |
| 页面与卡片间距 | 舒适 14px、紧凑 8px；组件间距至少 8px |

| 复选框图形 | 18 × 18px；通过整行标签扩大点击区域 |
| 手机输入字号 | 至少 16px，避免输入时浏览器自动放大 |
| 多行输入 | 通常至少 100px 高，允许纵向调整 |

表单列使用 `minmax(0,1fr)`；文本允许换行，长链接和结果允许在词内折行。320、390、430px 是必测宽度。桌面磁贴、能力磁贴和地图属于专用网格；手机单列要求主要针对表单和正文卡片，不强制将所有快捷按钮排成一列。

## 4. 组件契约

所有应用挂载在 `.amin-ui` 内，或将该类加在应用根节点。普通页面使用 `.amin-app-page`。已有骰子页使用等效的 `.amin-page.amin-dice` 流式布局。

| 类名 | 语义与行为 |
| --- | --- |
| `amin-context` | 当前对象、作用范围或一句操作说明，底部分隔 |
| `amin-tabs` | 紧凑横向分类，单行横滚；每个应用最多显示 5 个标签，其余收进行末“⋯”菜单（`ui/tabs.js` 的 `collapseTabs`）。当前选中的标签始终显示在行内 |
| `amin-more` | “⋯”菜单：按钮带 `aria-haspopup="menu"` 与 `aria-expanded`，菜单面板放在标签行／工具栏之后（不被横滚裁切）；方向键、Home / End 切换，Esc 关闭并把焦点还给按钮。手动“重新读取”等兜底操作也放在这里 |
| `amin-info` | 页内说明只保留一句，细节放进句末 ⓘ 的 `title` 与 `aria-label`（`ui/forms.js` 的 `infoNote`），ⓘ 可用键盘聚焦 |
| `amin-toolbar` / `amin-inline` | 可换行的操作行 / 内联信息 |
| `amin-stack` | 统一间距的纵向内容 |
| `amin-card` | 中性内容卡片 |
| `amin-section-heading` | 小节标题，可配元数据或局部操作 |
| `amin-form-grid` / `amin-field` | 响应式表单 / 标签与满宽控件 |
| `amin-check` / `amin-span-full` | 复选行 / 跨列表单项 |
| `amin-primary` | 当前区域的主要操作，通常一个 |
| `amin-meta` / `amin-help` | 次要信息 / 补充说明 |
| `amin-result` | 结果卡片，用侧边强调线突出 |
| `amin-empty` | 空状态说明，可附下一步操作 |
| `amin-notice` | 状态提示，空内容时隐藏 |
| `amin-savebar` | 集中的保存或提交操作 |
| `amin-scroll` | 专用 flex 布局中的明确滚动区 |

`.amin-app-card` 专指桌面启动磁贴，内容卡片使用 `.amin-card`。除 `.amin-app-page` 外，共享组件不添加 `app-` 前缀。

表单标签必须可见，说明放在字段附近；复选框与文字组成同一可点击标签。进度、错误、完成可以使用 `data-state="busy|error|success"`，同时显示具体文字。错误说明应指出发生了什么以及下一步可做什么。禁用状态不能遮蔽解释文字。

## 5. 共享变更操作

只有会覆盖、消耗或不可逆的操作采用「编辑 → 预览 → 确认一次 → 保存」流程：恢复存档、周期／行动结算、旅行、应用 AI 生成结果和删除。预览必须显示足够的业务结果，例如对象、原因、前后数量、时间、场景、关联模块或到期效果；不能把“保存”按钮同时当作未展示结果的直接执行按钮。

只新增记录或可以反向撤回的操作直接执行，不再单独预览：创建命名存档、收纳导入的存档、场景的快捷推进（10 分钟、1 小时、短休、长休等）与自定义推进，以及首页和楼层“快捷动作”里的短休、长休、推进 10 分钟。执行后在结果通知或结果卡中说明发生了什么，并提供“撤销”：优先使用应用已有的反向操作（例如把时钟设回推进前的时间，且仅在时钟未再变化时可用），否则使用操作前备份走“恢复”流程。撤销本身仍是一次普通保存，失败时同样显示“重试保存”。

确认前保存当前聊天、消息路径、回复候选和依赖状态的令牌。聊天、候选或依赖数据变化后，旧预览失效并要求重新预览。共享元数据写入使用同一互斥锁；一项操作确认或保存时，其他页面不能并发提交旧状态。

页面订阅所属服务的变更事件与聊天切换，数据变化后自动重绘；不在工具栏放常驻“刷新”按钮，兜底的“重新读取”放进“⋯”菜单。

确认只应用一次。保存失败时，已应用结果留在当前内存，页面进入待保存状态并停用新的变更操作；“重试保存”只持久化同一结果，不能重复扣除、转交、推进时间、旅行、掷骰或发动效果。错误区应说明已经发生的操作和重试的实际含义。

本地骰点分成三个动作：确定随机结果、把固定文本追加到聊天草稿、由用户使用酒馆发送按钮发送。能力发动和骰点追加也分别确认。应用不得调用官方 `/roll`、模拟 Enter 或自动发送消息。

页面上下文需要使用真实数据范围：

- “当前聊天 / 当前分支”表示当前聊天末尾与当前回复候选路径，不表示旧楼正文的历史快照。
- 世界状态旧楼层是明确标注的只读快照；浏览不会恢复变量。
- 能力库与部分预设明确标注跨聊天共享；生效记录仍归当前聊天。
- 跨应用存档恢复到当前聊天末尾，不改动或删除聊天消息。

## 7. 主窗口、楼层和 iframe

**主窗口**：普通应用由 `.amin-app-pane` 承担主滚动，内容页自然增长。手机根据 `visualViewport` 调整窗口位置和大小；打开时隐藏浮动启动器，保留头部关闭按钮。地图的专用内容区继续自行滚动。

**楼层窗口**：入口按钮和头部允许换行，窗口宽度受消息容器约束。手机忽略保存的桌面像素宽度，使用可用全宽；桌面保留独立宽度、对齐、统一高度或自动高度配置。普通应用由 `.amin-reply-floor-body` 承担主滚动。长原文、JSON 和受限选择列表可独立滚动，普通表单不要再套第二层主滚动区。人物卡、背包、关系与跨应用存档的楼层入口共享当前聊天 / 当前分支数据，不能把打开入口的旧楼号描述为独立历史状态。

**楼层工具栏排列**：进入“调整排列”后，桌面可拖动应用按钮，手机可长按后拖动；拖动期间显示位置提示，完成后记住顺序并同步所有楼层。普通浏览时保留聊天滚动，拖动结束不能触发应用打开。退出调整模式后恢复普通按钮操作。设置页同时提供上移 / 下移操作，让键盘用户和不便拖动的用户也能调整顺序；恢复默认仅恢复工具栏排列设置。

不常用入口可以收进“更多”。收纳后的应用仍然可用，展开“更多”后使用原按钮打开；这与关闭该应用的楼层入口是两种设置。按钮的原有事件、当前展开状态、可用性及世界状态历史入口行为必须保留。仅改变按钮排列或收纳位置时，不移动已经打开的应用内容，避免世界状态 iframe 重新加载。

整排按钮支持左 / 中 / 右对齐，设置独立于楼层窗口本身的对齐。排列、收纳和工具栏对齐属于用户外观偏好，不写入聊天记录、剧情存档或应用数据。缺少入口的楼层按保存顺序显示实际可用按钮；新入口仍应可见，旧偏好不能让新增应用丢失。手机工具栏及“更多”内容允许换行，不能撑宽消息正文。

**本轮变化小结**：联动在自动模式下应用一轮 `<amin_update>` 后，该 AI 回复楼层下方显示一行可展开小结（例如“本轮更新：+1 人物 · 生命 76→60 · 时间 +30 分钟”），展开列出逐项变化。只有最近一轮且之后资料未再变化时提供“撤回本轮”：使用应用前写入的操作前备份（没有外部存储时使用本次运行内存中的快照），走存档“恢复”流程并确认一次；聊天消息不变，撤回前的资料另存为安全备份。之后已有新的更新时按钮改为“已有更新，前往存档恢复”。审核模式下的待确认更新不显示小结。对已应用过更新的回复重新生成或切换候选时，每个聊天提示一次“上一版回复的更新不会自动撤回”。联动页另列本次运行内最近 10 组被拒绝的更新：时间、楼层、失败项、原因分类（格式 / 权限 / 引用 / 校验）与可折叠的原始 JSON。

**世界状态**：OS 磁贴在主窗口内打开完整工作台；最新有效楼层入口在消息下方打开完整工作台。两个入口共用当前聊天数据，切换入口时工作台显示在新选择的位置，不自动收起 OS 或从插件内跳转到楼层。主窗口沿用外壳的返回与收起控件；楼层窗口提供自己的收起按钮。隐藏楼层入口不影响 OS 内使用，空聊天发送首条消息后也不自动迁移。较早楼层展示只读快照，并提供前往当前工作台的入口。历史翻页不恢复变量。当前状态、生成和历史记录必须在文案上说明其作用范围。

**状态 iframe**：自行加载共享控件、主题同步和 `workbench-frame.css`；父页面不能直接为 iframe 内部布局提供 CSS。手机卡片单列，编辑操作单列，顶部工具可使用紧凑双列。工作台保留内部编辑区域；窗口过短或控件换行时允许外框滚动，避免内容无法到达。

### 桌面磁贴网格与配色

桌面可选择四列或六列正方形小格，默认为六列。桌面与手机保持相同格子坐标，缩小每格尺寸适应容器；不因屏幕宽度改变排列，也不在拖动后自动填补空洞。磁贴填满所占格子的整体区域，格间保留一致间距。

尺寸以“宽 × 高”的小格数量表达：小 1×1、小横 2×1、小竖 1×2、中 2×2、短宽 3×2、宽 4×2、短长 2×3、长 2×4。短宽和短长分别比原宽、长磁贴少一列或一行。1×1 也展示图标与名称，图标和字号随小格缩放；过长名称单行省略，通过 `aria-label` 和 `title` 保留完整名称。

编辑模式显示网格及额外空行。拖动时，指针所在格子始终作为磁贴左上角；预览必须标出整个目标矩形，而非仅标出指针所在小格。绿色实线与位置文字表示可放置；红色虚线及原因表示占用或越界，不能仅用颜色表达结果。释放到占用或越界区域时保留原位置，不挤动其他磁贴。预览层不得拦截指针或参与网格排版。结束编辑后隐藏网格辅助线和预览。

磁贴编辑保留无需拖动的位置调整方式。编辑器应显示当前磁贴与尺寸，位置修改、尺寸修改、删除和恢复默认的影响限于桌面偏好，不修改应用数据。位置与颜色刷新后保留。

每个磁贴可独立设置背景色、文字色、图标色，提供恢复默认配色入口；未自定义的磁贴使用应用默认配色。三个颜色字段有可见名称，颜色选择器不能脱离对应文字说明。自定义颜色需要在普通与 Windows 桌面风格和背景效果中一致生效；背景图片覆盖背景色，清空图片后显示背景色，编辑器需明确说明。应用内容页的主题保持独立。颜色选择允许用户自行搭配，因此不能宣称所有自定义组合自动满足对比度要求。

验收覆盖左上角落点、矩形整体预览、占用和越界拒绝、刷新后坐标保留、八种尺寸、320px 四列与六列不横向溢出，以及自定义配色和恢复默认。实际浏览器、模拟手机视口与物理手机结果分别记录。

## 8. 无障碍与反馈

代码已提供共享 `:focus-visible` 描边、原生按钮禁用样式、长文本换行和减少动态效果支持。多个页面已接入可见标签、`role="status"` 与 `aria-live="polite"`。

后续新增或修改页面应遵守：

- 操作使用真实按钮，并明确 `type`；非提交操作为 `type="button"`。
- 完整标签页使用 `tablist/tab/tabpanel`、`aria-selected`、`aria-controls`，支持方向键与 Home / End；互斥分类按钮可使用 `aria-pressed`。
- 输入框有可见标签，图标按钮有可理解的名称。提交错误应保留输入内容。
- 执行中明确说明状态，按业务使用 `disabled`、`aria-busy` 和取消操作；不得只用颜色或动画表示进度。
- 切换、生成和重新绘制后，焦点留在合理位置；不能因输入触发绘制而丢失焦点。

这些行为需要逐应用验证。统一 CSS 的存在不等于所有页面已完成读屏和键盘验收。

## 10. 样式维护入口

`base.css` 负责主窗口结构；`ui.css` 保留旧应用嵌入适配；`settings/appearance.css` 负责表面、品牌和楼层框架；`metro.css` 与 `desktop-effects.css` 负责桌面；`ui/standard.css` 负责共享控件、语义布局和响应式；状态 iframe 另外加载 `ui-status.css`、`settings/appearance-frame.css` 与 `apps/status/workbench-frame.css`。

未来修改先回到对应样式归属，不继续叠加重复固定配色与高优先级覆盖。共享约定同步维护到仓库内 `ui/README.md`。

磁贴整体布局设置：编辑器提供 4 格宽 / 6 格宽与整体大小（70%–100%）。缩放作用于整块磁贴网格并保持小格为正方形；窄屏不产生横向滚动。列数改变时保留仍有效的坐标，只将越界磁贴移入空位，图片、配色和应用入口不变。两项偏好持久化；恢复默认磁贴保留已选列数和整体大小。

小矩形磁贴采用两格分区：2×1 的左格放图标、右格放名称；1×2 的上格放图标、下格放名称。图标和名称分别在所属小格居中，名称最多两行，过长时省略。

## 11. 统一联动与跨应用资料（0.14）

- 功能扩展优先使用现有应用分页：世界状态的联动更新、剧情档案的事实与记忆、场景的日程与离场、人物的外观、关系的更新建议、能力的周期结算、存档的楼层检查点。
- 联动开关明确分为参与、读取、更新。更新必须同时允许读取；骰点只读。磁贴可见性不作为业务权限。
- 跨应用操作预览同时展示受影响应用、前后数据和原因；确认只提交一次。保存失败显示“重试保存”，不能让用户重复执行已经结算的动作。
- 名称供显示，操作选择使用稳定 ID。缺失引用明确展示；手动关联与应用自动生成的关联区分，解除关联不删除实体。
- 人物卡相互跳转使用稳定人物 ID。目标页面未找到人物时保持未解析状态，不按同名人物猜测。
- 模型更新块、JSON预览、来源原文等长内容限制在容器内换行或局部滚动。手机使用单列表单，可滚动分页和至少 44px 的主要触控按钮。
- 原世界状态 iframe 与联动页面切换时保留宿主窗口；联动更新生效后使旧状态视图重新读取，避免窗口消失或展示旧数据。

## 12. AI 资料生成（0.15）

- 五个资料应用共用折叠的“AI 生成／补充”面板，联合初始化位于联动页面。来源、范围与生成方式在提交前明确展示。
